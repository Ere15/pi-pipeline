# ORCA.md — пульт спринта для команды

Этот файл — для людей, которые **не запускают** pipeline, а смотрят результат
в приложении Orca. Ключей и терминалов не нужно.

## Где смотреть

- **Карточки worktree** — по одной на направление (`feat-*`) + `sprint-N-arch`.
  Имя, короткий статус, ссылки.
- **Статусы**: `todo` → `in-progress` → `in-review` → `completed`.
- **Красная точка (unread)** — нужно внимание человека. Рядом всегда comment что случилось.
- **Ссылки на карточке** — PR и issue, которые закрывает направление.

## Документы спринта (в репо)

- `runs/sprint-NN/REPORT.md` — итог: что сделано, чем доказано, траты, блокеры.
- `runs/sprint-NN/REVIEW.md` — вердикт ревью + must-fix.
- `ROADMAP-NN.md` — цели, scope/non-goals, задачи.
- `docs/arch/ADR-NN-*.md` — архитектурные решения (что/почему/что отбросили).

## Как читать статус

Комментарий на карточке — это чекпоинт: `repro ok`, `fix implemented`,
`tests green`, `review passed`, `blocked: <причина>`. Свежий комментарий =
свежее состояние. Тишина дольше 2 часов при статусе `in-progress` — повод спросить.

## Как вмешаться

- **Забрать задачу**: откройте worktree — код, ветка и история на месте.
- **Ответить на вопрос**: красная точка + вопрос в комментарии — отвечайте там же,
  координатор заберёт ответ и продолжит.
- **Не трогайте**: терминалы воркеров пока карточка `in-progress`/`in-review`
  (идущая работа упадёт). Дождитесь `completed` или красной точки.

## Что означают гейты

- Архитектура утверждена → можно пилить.
- Интеграция зелёная → направления сошлись, можно ревьювить.
- Must-fix пуст → можно мержить.
- Merge делает координатор сам после зелёного CI — кнопку жать не надо.
